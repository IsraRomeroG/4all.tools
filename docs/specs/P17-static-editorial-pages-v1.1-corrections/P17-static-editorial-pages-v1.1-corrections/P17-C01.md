# P17-C01 — Static Editorial Pages Contract Closure

> **Correction ID:** `P17-C01`
> **Version:** 1.0.0
> **Status:** Ready
> **Applies to:** `P17-static-editorial-pages-v1.0`
> **Baseline:** current `main` after commit `75d9dc9ba047bcd6aee13981b0dc563a5d6e527d`
> **Risk:** Low

## Purpose

Close the remaining verification and YAGNI gaps in P17 without changing its production architecture, publishing a real static editorial page, or modifying any public URL.

P17 already introduced the reusable static-page publishing family. This correction package does **not** redesign that family. It adds the missing durable evidence required by the original P17 specifications and removes one transient composition value that does not belong in the final `StaticPageModel`.

The target correction flow is:

```text
existing P17 production implementation
        ↓
exact content-query contract tests
        ↓
composer + root-adapter integration tests
        ↓
static-page collision / reserved-namespace guardrails
        ↓
remove unused localized cluster from returned page model
        ↓
public-route parity + full verify
        ↓
P17 Complete
```

## Starting State

The repository already has:

- `staticPages` registered in Astro Content;
- strict `StaticPageId + locale + routeSlug + status + title + seo` content schema;
- shared published-content indexing for static pages;
- `RouteTarget.kind = 'static-page'`;
- `area = 'static'` route publication;
- one-segment localized path projection through the existing root adapter family;
- `StaticPageModel`, `composeStaticPageModel()`, and `StaticPageTemplate.astro`;
- static-page SEO indexability support;
- no production Markdown entries under `src/content/static-pages/`;
- no `static-page` records in the approved public route inventory;
- a green GitHub Actions `Verify` workflow at the correction baseline.

The remaining gap is evidence, not architecture.

## Correction Scope

### Required

1. Add direct tests for the public static-page query API.
2. Add integration coverage for the static-page composer using localized fixture content without publishing real content.
3. Add integration coverage for root adapter dispatch of both `tool-category` and `static-page` targets.
4. Prove the root adapter behavior across all supported locale families without creating new page files.
5. Add explicit static-page collision and reserved-namespace guardrail tests.
6. Stop returning the intermediate localized route cluster from `composeStaticPageModel()` when the final page model has no consumer for it.
7. Re-run the full verification pipeline and prove that the public route inventory remains unchanged from the correction baseline.

### Explicitly Not Required

- new production Markdown under `src/content/static-pages/`;
- `/contact/`, `/privacy/`, `/terms/`, or any other real static page;
- changes to `PUBLIC_ROUTE_INVENTORY` caused by P17-C01;
- redirects or `.htaccess` rules;
- a new route registry or route provider;
- a new content repository abstraction;
- a second one-segment Astro route family;
- browser E2E tests for static pages;
- new dependencies;
- schema expansion;
- breadcrumbs, forms, footer changes, legal metadata, JSON-LD, or page hierarchy.

## Authority Invariants

The correction must preserve the P17 authority model:

```text
published staticPages content
  → localized availability + routeSlug + editorial body + SEO input

RouteRegistry
  → canonical public route + localized route variants

composeStaticPageModel()
  → resolved delivery model

StaticPageTemplate.astro
  → presentation only
```

No test seam may introduce a new production authority solely to make testing easier.

## Public Route Freeze

P17-C01 starts from the public route inventory already approved on current `main`.

The correction must not add, remove, or rename a public route.

In particular:

- existing `/es/desarrollo/` belongs to the current baseline and is not a P17-C01 route addition;
- no `target.kind = 'static-page'` entry may be added to the production public route inventory;
- no placeholder static-page route may appear in build output;
- English remains unprefixed and `/en/` must not appear.

If route parity changes while implementing this correction, stop and treat it as an unrelated migration requiring its own review.

## Test Policy

Tests must protect observable contracts, not implementation trivia.

Prefer:

```text
fixture content/indexes
  → public query / RouteRegistry / composer / adapter
  → observable result or typed failure
```

Avoid tests that assert:

- private helper names;
- import text;
- exact internal call counts unless they protect the shared-snapshot contract;
- DTO freezing;
- private wrappers;
- mock-only APIs added to production code.

Production code should not gain dependency injection solely to satisfy these tests.

## Definition of Done

P17-C01 is complete only when all of the following are true:

- public static-page queries have direct exact-match coverage;
- missing locale and duplicate published identity behavior are explicitly tested;
- `composeStaticPageModel()` is proven with at least two localized translations of one stable `pageId`;
- canonical URL, localized alternates, language-switcher availability, missing canonical, and missing localized content are covered;
- root adapter dispatch is proven for both `tool-category` and `static-page`;
- adapter behavior remains valid across English, Spanish, Portuguese, and French route families;
- static-page vs root-category collision is explicitly rejected;
- static-page vs static-page collision is explicitly rejected;
- a static page claiming a reserved root segment is explicitly rejected;
- `composeStaticPageModel()` does not return an unused localized route cluster;
- no production static-page content exists;
- no static-page route is added to `PUBLIC_ROUTE_INVENTORY`;
- existing public routes remain unchanged from the correction baseline;
- no redirects are added;
- no dependencies or lockfiles are changed;
- `npm run verify` succeeds locally;
- the pushed closing SHA has GitHub Actions `Verify / verify` green.

Once these conditions are satisfied, P17 can be marked **Complete**.
